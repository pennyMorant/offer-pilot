# 目的地评估与连续配送流程

这是既定核心链路的延续：订单识别 → 当前价值 → 目的地区域参考 → 接单 → 配送占用 → 明确完成后继续。

## 目的地识别与地址解析

DeliveryLocationParser 仅提取明确标签的商家、取餐位置和送达位置，支持 Destination、Drop-off、Deliver to 及对应中文标签。多个不同目的地不任意选一，无标签地图文字不当成精确地址。

显式坐标直接映射到网格；geo URI 含 q 参数时按命名位置处理，不把 geo:0,0 占位坐标当作送达点。普通地址通过 Android 系统地理编码解析：Android 13 起用回调，较旧系统通过单工作线程和有界队列处理。

单次系统查询等待最多约六秒；请求间隔至少五秒，排队期间仍显示解析中，超时回到未知。查询与报价采集、计算、点击分离。候选跨多个网格时标记歧义，只有城市等宽泛信息时不映射成精确网格。地址或街道结果明确标注为估计。

本应用最多保留 64 个内存解析项，成功项最多六小时，失败项短时缓存；工作结束时清空。查询使用系统地理编码服务，可能依赖网络；原始地址和解析结果不写入数据库。

## 历史区域质量评估

先以可信总耗时估计送达时段，再查询相同平台、当前手机时区、质量版本 1 的历史汇总。总耗时未知时只提供地区整体参考，不编造送达时刻。

按以下顺序选择证据：

| 范围 | 最少可分类样本 |
| --- | ---: |
| 同地区、同星期、同一小时 | 10 |
| 同地区、送达前后一小时 | 15 |
| 同地区、不同星期的同一小时 | 20 |
| 相邻九宫格、同星期和小时 | 20 |
| 同地区整体基线 | 30 |

每档还要求至少一半观测样本具有完整分类依据。满足要求后，优质占比至少 50% 且低价值不超过 25% 时标为历史质量较好；低价值至少 50% 时标为偏低，其余为一般。样本不足显示未知和实际样本数。

界面显示参考范围、位置精度、手机时区与优质比例。该比例描述历史报价质量，不是未来收到报价的概率。真实下一单等待、空驶和目的地接单概率仍需要后续独立汇总数据。

异步结果绑定当前报价指纹和目的地文本；切换报价、结束工作或取消查询后，不发布旧结果。缓存与限速使用单调时钟。

## 配送占用与自动接单开关

用户开关意愿 autoAcceptEnabled 与当前是否可执行 automatic 分开。

- 开启且工作/权限/规则正常时可执行自动接单。
- 点击发出后进入待确认，继续保留用户意愿，但暂停下一次自动动作。
- 明确接单或进行中界面可确认占用；手动接下的配送也可依据明确进行中动作建立一个占用状态。
- 只有先观察到同平台进行中的配送，再在最近 30 秒内看到完成界面，且完成信号在相邻采集间隔内持续至少约 600 毫秒，才自动解除占用。
- 解除后开关意愿仍开启、工作/权限/规则正常时继续；用户配送中关闭开关则不恢复。
- 历史订单页、报价卡混入及冲突信号不作为配送完成。未知状态保持占用，允许人工核对。
- 人工核对、结束工作、进程重启、规则保存或采集异常关闭自动意愿，不静默恢复。

数据库仍只有一个 active 恢复槽位。完成状态更新同一槽位，没有逐单配送日志、地址、轨迹或结算明细。

配送识别依赖明确界面文本；缺少平台订单 ID 时存在识别与覆盖限制。没有明确证据时不把报价卡消失解释为成功或完成。

## 当前实施结论

当前报价卡与悬浮窗已接入目的地历史参考，配送观察器已接入自动接单流程。代码仅经静态审核，未运行编译、测试或模拟器；没有真实平台兼容或运行结论。
