# Shizuku 采集增强：本轮范围

## 结构化节点与报价容器

特权服务现在构造临时节点模型，包含遍历索引、父节点索引、文本、描述、资源 ID、窗口、包名、屏幕边界和可见/启用/可点击状态。开启资源 ID 获取；节点模型只存在内存，不保存页面或订单明细。

解析只读取目标应用当前窗口中的可见且有有效边界的节点。先检查全页分类，历史、配送阶段、冲突、追加单及叠单不能通过缩小容器隐藏。普通报价页只有一个明确接单动作时，向上最多检查 8 层容器；只有容器内具备可信金额、明确总里程、总耗时、商家和目的地，且节点边界均位于容器内，才使用该容器文本。否则回退到可见全页文字，不根据距离猜测字段归属。

快照和点击前复核使用同一套组装逻辑。最多 450 个节点、深度 35、每节点 100 个子节点、原始文本总量 30000 字符；超过上限返回采集错误，不能静默截断后点击。快照增加节点数量、选中容器索引和窗口 ID，未增加节点诊断页面或导出。

这是一种保守的容器筛选，不是对所有真实 Uber / DoorDash 布局的完整适配。资源 ID 已可读取，但尚无真实版本 ID 白名单；无法找到容器时仍可能需要人工处理。

## 事件触发采集

UiAutomation 监听窗口切换、窗口列表变化、内容变化、滚动及文字变化。平台内容事件和任意应用的窗口切换只发送一个无订单内容的唤醒信号，通过 oneway AIDL 回传。

特权端用 120 毫秒合并事件；应用使用容量为 1 的合并队列，串行执行采集，至少间隔 250 毫秒。没有事件时等待约 1.5 秒再兜底采集；读取耗时计入实际间隔，不宣称固定刷新频率。连接变化后重新注册，旧连接回调不被使用；回调不可用时仍保留兜底采集。

相关 Android 依据：[UiAutomation 事件监听](https://developer.android.com/reference/android/app/UiAutomation)、[资源 ID 获取标志](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo#FLAG_REPORT_VIEW_IDS)。

## 中断保护

- 应用检测屏幕可交互且未锁定，在采集开始、异步结果返回和接单前检查。锁屏/熄屏或离开支持的平台页面后关闭自动接单意愿，不自动解锁设备。
- 每次采集有独立 5 秒看门狗，不等待采集持有的互斥锁。超时关闭意愿、清理报价展示；已发出接单且占用未决时转为待核对。迟到的解析结果不能重新填回报价或触发接单。
- 工作代次隔离，结束并重新开始工作后旧看门狗不能覆盖新会话；连接变化使旧采集失效。
- OCR 返回后重新读取节点快照，窗口 ID 或报价指纹变化即丢弃本帧，不拼接不同画面。仍是整屏 OCR，尚未实现局部截图识别。
- 首步和确认动作均携带系统单调时钟的 2 秒期限，特权服务在入口和实际调用点击前检查。调用回复晚于超时状态时，不重新开启后续确认，也不覆盖待核对提示。

看门狗不是强制取消 Binder：阻塞的调用可能仍占用线程和工作流锁，后续采集会等待它返回，必要时需要结束工作或重启应用。期限只能阻止过期指令开始执行，不能撤回已进入系统的点击；不明结果继续保留占用，不自动重试。锁屏检查和点击也不是原子操作。本轮没有实现远程进程自动重建或挂起线程强制终止。

AIDL 已更新，UserService 版本提升至 4；更新 APK 后应结束旧工作再重新开始。
