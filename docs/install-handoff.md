## 手机使用

1. 安装本次 APK；手机上已有同签名 Overud 时可以覆盖安装。签名不一致时不要直接卸载，以免丢失本地汇总；先核对原安装包来源。
2. 手机启动 Shevery，在 Overud 工作台检查连接并授权。更新后结束旧工作再重新开始，以连接新版特权服务。
3. 保存 Uber Eats / DoorDash 对应要求；需要地区统计时授予位置权限，需要切换到平台后看报价时开启悬浮窗权限。
4. 点击开始工作，进入平台报价界面。自动接单需要另外开启；OCR 单独识别、未知字段或不符合已启用门槛的报价不会自动点击。
5. 确认页若缺少原报价对应信息，会停止自动确认并提示核对。请回到平台处理；不要把 Overud 的点击提示当成平台已经接单。
6. 配送期间暂停自动接单。无法确认结果时保留占用；只有核实平台确实没有进行中的配送，才使用人工解除入口。

## 当前边界

- 已有报价分析、可配置自动接单、平台首步动作复核、一次性确认、确认超时与小时汇总。
- 多步确认要求金额、商家、目的地和总路线完整一致；未识别布局可能需要手动操作，追加单仍不自动执行。
- 15 秒是点击返回后的结果等待窗口；另有 5 秒采集看门狗和 2 秒指令期限，但不能强制取消已经进入系统的调用。
- 尚未确认手机上的 Uber / DoorDash 版本能否提供这些节点和标签；不能保证明天所有报价都能自动接单。
- 目的地只提供已有历史样本的质量参考。新安装缺少历史数据，不会生成下一单概率或市场需求预测。

构建成功和真实订单适配是不同结果。当前交付用于安装，真实平台覆盖率与实际接单行为仍未验证。


## 手动图片测试

旧包从工作台进入图片测试。当前 Debug 源码从“设置 → 开发工具 → 订单图片识别”进入；无需启动工作或连接 Shevery，系统选图器只授予所选图片的读取权限，不申请相册全量访问。

显示页面类型、报价字段、估值、已保存规则的未通过原因和可复制的 OCR 原文。图片来源保留 OCR 限制，永不触发真实接单；不查询目的地区域、不写入统计、不保存图片或原文。关闭窗口清除结果，取消选图保留原结果。大图按最长边 3072 像素缩放并处理图像方向；OCR 与现有实时流程使用相同的 Latin 模型，不能据此承诺中文截图覆盖率。

## Prop 22 估算

在规则页启用 Prop 22，填写取餐地适用最低时薪、机动车与假设小费比例，保存后识别报价即可查看估算。默认关闭，不自动判断城市；本次提供 2026 标准。真实补差按平台周期核算，并非每单保证到账。见 `prop22-estimates.md`。


## 驾驶语音

规则页开启“驾驶语音播报”，先在停车时点击“试听中文”。需要系统已安装离线中文语音，缺失时由设置页入口进入系统安装。开始工作后自动播报实时订单，通知栏“关闭语音”可立即静音并保存关闭状态，不结束订单监听。没有申请麦克风权限。

当前 APK 编译成功，未在手机验证中文音色、导航共存或蓝牙路由。详见 `voice-announcements.md`。
